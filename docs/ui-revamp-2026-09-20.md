# UI revamp · 20 September 2026

## Why

The course strip at the top used two rows of 68 px cards (about 150 px before any content), the course page opened with a 42 px title, a 42 px stat and a dropdown-based launch panel, and downloads sat behind `<details>` toggles. The older design read better: a dark rail with the MED//25 mark and dates, small course cards, a compact exam chip and title, and stat tiles.

## What shipped

**Shell** (`src/components/StudyShell.tsx`, `app/mcq.css`)

- Dark 196 px rail: MED//25 mark, "Term 1 + Term 2", the three Term 1 dates, the four destinations with icons, and the storage status at the foot.
- One-row course strip: term segmented control plus a chip per course (name, count, and the sitting date when one is known; "Date TBA" stays in the chip tooltip and the page eyebrow). Chips wrap at narrow desktop widths and scroll horizontally on phones.
- Phones: the rail becomes a bottom tab bar (icon + label, safe-area aware); the top bar carries the mark, term control and the scrolling course strip.
- Immersive mode is unchanged: answering hides all chrome (`.mcq-immersive`, `.final-exam-shell`, `[data-cvs-paper-session="active"]`).

**Course header** (shared by every tab, `app/page.tsx`)

- Eyebrow chip "Term 2 exam · Date TBA", 26 px title, one two-line description from the exam config, the MCQ count, and pill actions: **Review PDF · 192 pp** (cached download, status in the tooltip) and **Past papers**.

**Practice**

- Launch panel: collection **chips with counts** replace the dropdown and double as the stat tiles; session length and feedback mode are segmented pills; **Start practice** sits on the same row; a hint line shows the effective size and seen/unseen split. Empty saved collections are disabled instead of hidden.
- Quick pills: Review mistakes · n, Flagged · n, Practise a review section, Results · n.
- Resume strip for an unfinished session.

**Past exams** (`src/components/PastExamHub.tsx`, `PastPaperCard.tsx`)

- Compact cards: label + Source details popover, title, scored/source/ungraded counts, saved result, **Take paper** / New attempt, and always-visible download pills (Questions, Answer key, Questions + key, Original).
- Combine papers moved below the cards as a compact panel with pill checkboxes.
- CVS keeps its own hub; its module styles are tightened to the same pill and card language (`CvsPastExams.module.css`).

**Review topics** (`src/components/CourseReview.tsx`)

- Section header with count, a rounded search field, volume filter and "With MCQs only" pill; two- or three-column compact rows with an index badge, MCQ count, **PDF p. n** link pill and **Practise** accent pill.

**Results**

- One row per session: date, scope, correct/answered/mode, a colour-coded score pill, **Open review**.

**Session and review screens**

- Same button language (pill primaries, 56 px header bars); footer nav columns are `auto 1fr auto` so "Next question →" no longer wraps.

## Follow-up · past papers unified, typeset PDFs, subject-grouped review

**One past-exam hub for every course.** CVS no longer has its own layout. Every course shows the same sequence: section head → toolbar (all-paper bank, source archive where it exists, **All papers + keys · PDF** bundle, **All downloads** panel) → **Combine papers** at the top → the paper grid. The CVS **Core Exam** and **Non-core Anatomy** sets are ordinary cards in that grid (`PastPaperCard featured`), with their subject counts, saved results, Start / Anatomy-only / New-attempt actions and the recurrence evidence behind a compact disclosure. Every CVS paper card carries the same download pills as the other courses, mapped by collection id from the downloads catalog (`src/components/PaperDownloads.tsx`).

**Typeset PDFs.** This pass first generated the 90 question / answer-key / combined PDFs and 5 course bundles with a Node script and headless Chrome and committed them (about 80 MB). That approach was replaced the same day by on-device typesetting; see the follow-up below. The design described there (cover, question cards, inline keys, key table, footers) is the same.

**Selected paper.** The back pill, title, note and download pills form one header; the final-exam engine drops its own eyebrow and "Final exam mode." heading when a paper is selected, which removes the cramped double heading.

**Review sections.** Rows are single-line (index, title, MCQ count, PDF page pill, Practise pill) in two columns from 1100 px. When the course's mapped questions span two or more subjects, sections are grouped and filterable by Anatomy, Histology, Embryology, Physiology or Biochemistry. A section's subject is the majority subject of its mapped MCQs; sections without MCQs join the surrounding block so the TOC order is kept. Single-subject courses stay grouped by review volume.

Verified: TypeScript, 23 regression checks (including every download URL resolving), production build, and headless-Chrome captures of CVS, Nutrition and Religion hubs (desktop and 390 px), the all-bank home view, a Religion paper session, and the grouped CVS review list.

## Follow-up · PDFs typeset in the browser

The 95 pre-generated PDFs (about 80 MB) are gone. A download pill now typesets its PDF on the device:

- `src/lib/paper-pdf/parse-export.mjs` parses the existing Markdown exports (the shape is machine generated and stable) into questions, options and keys; `tests/paper-pdf.test.mjs` runs it over all 30 collections and checks counts against the catalog.
- `src/lib/paper-pdf/document.ts` builds a pdfmake definition that mirrors the earlier design: cover with course, collection id, counts and sources; numbered question cards with lettered options; the correct option and the answer notes inline in the questions-plus-key variant; a key table with provenance; page footers with numbers; one page-break per paper in a course bundle. Arabic runs switch to Noto Sans Arabic; everything else uses Noto Sans (`public/fonts`, about 1.5 MB, fetched once on first use and cached by the browser).
- `src/lib/paper-pdf/client.ts` fetches the Markdown, hashes template version + variant + text + metadata with SHA-256, and looks the key up in Cache Storage (`med25-paper-pdfs-v1`). A hit returns instantly; a miss lazy-loads pdfmake (about 330 KB gzipped, only on the first tap), renders, stores the Blob, evicts older versions of the same document and keeps at most 60 entries. Editing a paper or bumping `PAPER_PDF_TEMPLATE` therefore regenerates on the next tap without any manual invalidation. Only same-origin `/study/**.md` sources are accepted; answers and results never enter this cache, and the existing PDF cache and service worker are untouched.
- Pills report progress inside the pill (spinner, check, or a red mark) with the detail in the tooltip; no text is printed beneath them.
- The catalogs point `downloads.*` back at the Markdown files; the bundle pill passes every collection of the course.

Verified: 27 regression checks (parser, builder, cache behaviour with fakes, no published PDFs remain, plus the existing MCQ and PDF-cache suites), TypeScript, production build, and a headless-Chrome run that clicked the pills with downloads enabled: the first tap typeset a valid PDF and stored it, the second tap reported "Opened from device cache" with no re-render, and the answer-key and course-bundle pills produced valid PDFs. The generated pages were thumbnailed and checked by eye.

### Independent review (gpt-5.6 via Codex, read-only) and what changed

The review ran the suites and TypeScript, rendered all 30 combined exports through pdfmake 0.3.11, and checked the cache logic and pdfmake semantics. It found four defects, all fixed:

- The bundled fonts lack `→` and `≈`, which occur in 10 and 6 exports respectively; pdfmake would have drawn `.notdef` boxes. `runs()` now maps a small set of arrows and `≈` to renderable equivalents (`glyphFallbacks` in `document.ts`), and a new test builds every collection in every variant, walks every text leaf with its resolved font and weight, and checks each character against the real font files with fontkit. A new export with an unsupported character fails the suite instead of shipping boxes.
- Arabic source names on the cover, the inline answer text and the footer label bypassed the Arabic font switch; they go through `runs()` now.
- Pills exposed their status only as a tooltip, and the original-PDF pill replaced its accessible name with the status. Both pills now share `useDownloadPill()`: the visible label stays the name, a visually hidden `role="status"` span announces progress and completion, `aria-disabled` is set while busy, repeat clicks are ignored through a ref (not stale state), and no state is set after unmount. Native `disabled` was deliberately not used because it drops keyboard focus mid-operation.
- A slow render finishing after a fresher one could prune the fresher copy. The client remembers the newest key per document path, never prunes that key, and prunes on cache hits as well, so a superseded copy disappears on the next tap. `cache.put` and pruning are also reported separately (a prune failure no longer reports "not saved"). The font file list is part of the hash input; swapping a font file under the same name still needs a template bump.

Remaining suggestions that were not adopted: deduplicating concurrent requests before the Markdown fetch (the fetch is same-origin and cheap), and revoking object URLs on unmount (an early revoke can cancel an in-flight save; the 60-second timer stays).
